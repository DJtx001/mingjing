# BM25 语义门控与检索质量评测纪实

> 时间：2026-10-09 ｜ 关联提交：`5d39604`（修复）、评测脚本（本目录同批）
> 一句话：闲聊/时间类问题会被 BM25 词面命中硬凑满 4 法条 + 3 案例的引用卡片，修法是给 BM25 召回加「语义门控」，并落地一套轻量检索评测把「改没改好」变成硬指标。

---

## 一、问题现象

线上 AI 助手回答「现在是什么时间」时，正文答完时间后，引用卡片硬塞了 7 条毫不相关的法条与案例：

```
法条 《最高人民法院关于审理企业破产案件指定管理人的规定》第二十三条
法条 《中华人民共和国涉外民事关系法律适用法》第二十条
法条 《中华人民共和国档案法》第二条
法条 《中华人民共和国民法典》第二百零三条
案例 赠与合同纠纷（（2019）沪0117民初5688号）
案例 确认劳动关系纠纷（（2017）苏05民终1050号）
案例 合同纠纷（（2019）豫0928民初1182号）
```

诉求：**不需要引用的场合不该硬给 7 条，搜到几条就是几条。**

---

## 二、根因分析（知识点）

检索链路是「混合召回」：向量语义 + BM25 全文，RRF 融合排序：

```
retrieve(query)
 ├─ 向量路：embed → Chroma 查询 → 按 cosine 距离阈值过滤
 ├─ BM25 路：jieba 分词 → BM25Okapi 打分 → 只过滤 score ≤ 0
 └─ _rrf_fuse：两路按 ref_id 合并，RRF 打分取 top_k
```

问题出在三个环节的分工错配：

### 1. 只有向量路有相关性阈值
`retrieval_service.py` 里 `MAX_DISTANCE = 0.42`，注释里写明了校准依据：**实测真相关 ≤0.39、无关 ≥0.57**，取 0.42 留 0.03 边际，宁可漏不错报。

### 2. BM25 路没有相关性阈值
`bm25_service.py` 的 `search_laws/search_cases` 只过滤 `score <= 0`。只要查询词与法条/案例有**任何词面重叠**就召回。而「现在是什么时间」里的「时间」「什么」在法条里高频出现（诉讼时效、期间计算……），jieba 切词后必然命中，分数还不算低（实测 10~19）。

### 3. RRF 融合只看排名，不看绝对相关性
`_rrf_fuse` 对两路候选做倒排融合，取 `top_k`（法条 4、案例 3）。它不关心每条是否「真相关」，只会把垃圾里排名靠前的 4+3 条挑出来——这就是「硬给 7 条」的机制来源。

**根因一句话**：BM25 的「词面命中」在没有「语义相关」佐证时，把无关查询的 top_k 名额填满了。

---

## 三、修复方案：语义门控

思路：**BM25 只在向量路证明「查询与知识库语义相关」之后才参与召回**。向量路是贝叶斯意义上的「先验」——它说这个查询和法条语义不相关（全部 0 命中），就根本不信任 BM25 的词面命中。

改动仅在 `retrieve()` 两处，各一行：

```python
# 改前
b_laws = bm25.search_laws(query, top_laws * 2)
# 改后
b_laws = bm25.search_laws(query, top_laws * 2) if v_laws else []

# 案例路同理
b_cases = bm25.search_cases(query, top_cases * 2) if v_cases else []
```

门控语义：`v_laws`（通过 `MAX_DISTANCE` 阈值过滤后的向量命中）为空 → `b_laws` 直接空、跳过 BM25。查询与知识库无语义关联时，整体检索返回空 → 上游落回既有的 `_fallback_reply`（时间/问候直接后端答，零引用卡片、零 LLM 调用）。

`# ponytail:` 注释标了已知边界：**纯词面匹配的查询（人名、案号）若向量 0 命中会被全弃**，由 Function Calling 的 DB LIKE 工具兜底。

## 四、验证方法（真实数据探针）

### 4.1 一个关键坑：BM25 是异步加载的
`BM25Service.__init__` 起后台线程 `_load()` 建索引，首次查询时若未 ready，`search_*` 直接返回 `[]`。如果探针脚本一启动就跑第一个查询，会拿到「全 0 召回」的假阴性——**那是没索引，不是没召回**。正确姿势是先 `get_bm25_service().ensure_loaded()` 再测。

### 4.2 样本评估
本地对 8 个无关查询 + 6 个真法律问题打分数分布，得到干净的分界线：

| 类型 | 向量命中数 | BM25-only 分数 |
|---|---|---|
| 无关查询（时间/闲聊）×8 | **全部 0** | 6.3 ~ 19.4 |
| 真法律问题 ×6 | **全部 ≥4** | 19.8 ~ 43.1（有效补充） |

据此确认门控信号可靠：向量 0 命中 ⇔ 无关，BM25 该不该参与一眼可判，无需凭空设 BM25 绝对阈值。

## 六、评测建设：为什么要这样评

### 6.1 对 Ragas + LangSmith 的取舍（知识点）
- **LangSmith** 是给长链路 / agent 调试用的可观测平台（trace、隔离评测）。本项目检索链路是手写的 `retrieve()` → `_rrf_fuse()` 三段式、本地可复现，上它只是给短链路加平台依赖，收益低。
- **Ragas** 里能评「检索召回质量」的指标（`context_recall` 等）**需要 ground truth 上下文**；而它最出名的 `faithfulness / answer_relevancy` 是**生成侧** LLM-judge——评「回答是否忠于材料」而非「召回了什么」，且每次判分都调 DeepSeek/DashScope 按量计费、指标带 LLM 噪声。
- 结论：先做**检索侧**指标，用本地脚本 + 标注集零成本拿到同一答案，避免为一个布尔式门控改动引入一整套 LLM-judge 流水线。

### 6.2 落地方案（两个文件）

| 文件 | 作用 |
|---|---|
| `scripts/retrieval_queries.json` | 标注集：30 正例 + 20 负例。正例标注预期法条来源关键词 / 案例标题关键词，负例期望召回 0 条 |
| `scripts/retrieval_eval.py` | 自包含评测脚本，一次命令出改前/改后对照表 |

**指标定义**：
- `误召回率` ＝ 负例中「召回 >0 条」的占比（越低越好，目标 0）
- `law hit@4` ＝ 正例前 4 条法条里至少 1 条相关的占比
- `case hit@3` ＝ 正例前 3 条案例里至少 1 条相关的占比

**评测脚本的一个设计取舍**：不复用生产 `retrieve()` 本体，而是内嵌一份逻辑副本，用 `gate` 参数切换改前/改后——目的就是把「改前基线」作为**历史快照钉死在评测里**，生产函数以后怎么演进，评测都能回答「比改前好还是差」。

### 6.3 结果

| | 误召回率（负例） | law hit@4 | case hit@3 | 负例误召条数 |
|---|---|---|---|---|
| **改前**（无条件召回） | 100% | 100% | 100% | 119 条 |
| **改后**（语义门控） | **10%** | 100% | 100% | 8 条 |

- 误召回 100% → 10%，垃圾引用 119 条 → 8 条
- 正例召回无损（100% / 100%），BM25 该补的高分相关条目一条没丢

## 七、结论与遗留

> 本节为第一代（50 条评测集）口径的结论，历史保留。2026-10 已扩集至 200 条并引入意图门控，见第九节。

1. **修复目标达成**：闲聊/时间类问题不再硬凑满额引用，真问题召回无损。
2. **剩余 10% 成因**：漏网 2 条「股票怎么买」「你觉得我该不该辞职」是**半专业沾边**查询——向量路给了 `dist=0.352`（证券法规，真沾边）、`0.355~0.396`（劳动安置/公务员法），弱命中一开 BM25 就被放行。
3. **收口方向**（未做，有召回副作用）：把门控阈值从 `dist≤0.42` 收紧，或给 BM25-only 条目加绝对分数门槛。会误伤正例里同样靠 0.36~0.42 弱命中召回的情形，故暂不调。
   - 2026-10 更新：本条方案**已被 200 条数据证伪**——"单查向量距离"这条线不成立（负例「股票怎么买」0.352 落在正例分布内部，报警类 0.278 更低）。最终改用「案例侧命中数 + 法条侧距离」的联合条件实现，见第九节。

## 八、可复用的知识点清单

- **向量 cosine 距离阈值**是唯一有实测校准的相关性先验（真相关 ≤0.39 / 无关 ≥0.57），BM25 分数没有天然绝对阈值，别硬造魔法数。
- **混合召回的分工**：向量管「是不是相关」，BM25 管「相关前提下补词面召回 + 重排加分」；让 BM25 独立召回 = 让词频替语义做主，无关查询必然污染。
- **RRF 只排序、不把关**：融合层不会替你排除弱相关，门的职责必须在入池前做。
- **异步索引的坑**：探针/评测脚本必须先 `ensure_loaded()` 再测，否则把「未就绪」误读成「无召回」。
- **评测先评检索、后评生成**：生成侧（faithfulness 等）是 LLM-judge，花钱且不回答「检索准不准」；检索侧用标注集 + hit@k / 误召回率即可，零成本且可固化为回归测试。
- **「案例侧零命中」是比距离更干净的跨域信号**：法条是规范文本（"办理/申请/规定"），生活问题能蹭到近邻；案例是具体纠纷，生活问题够不到。以案为域 > 以法为域。
- **标注集的分类标准必须是「可回答性」而不是「问题类型」**：把程序咨询（"护照怎么申请"）标成负例会调错靶子——分类标准写错，后面所有标定都是在解一道错题。

## 九、第二代：200 条扩集 + 意图门控（2026-10）

### 9.1 为什么要重做评测集

第一代 50 条（30 正 + 20 负）的两个问题：

- **负例构成偏闲聊**（时间/问候/天气），"半专业沾边"类只有 2 条——恰好就是漏网的「股票/辞职」。样本太窄，测不出这类。
- **正例标注关键词没对齐知识库真实 source 名**（如"彩礼"标了别的词），26 条是假性未命中。

扩集动作：写满 200 条 → 逐条跑检索比对真实召回内容 → 修正 26 条标注关键词 + 18 条程序类负例搬为正例（纠偏，见 9.2）。

### 9.2 分类标准纠偏（本次最大的教训）

初版把「住房公积金怎么提取」「护照怎么申请」等 18 条程序咨询标成了负例（按"半专业沾边应拒绝"），内容核对后发现知识库条文**直接回答**了这些问题。

> 分类标准：**召回内容能否直接回答该问题**。回答得了 = 正例（召回正确）；答非所问 = 负例（误召回）。
> 不是"问题够不够法律"，是"知识库答不答得上"。

最终规模：**138 正例 + 62 负例 = 200 条**。

### 9.3 特征探索：两大特征族被数据否决

为区分"半专业沾边"负例，对 200 条全量探了向量距离 + BM25 分数：

| 假设 | 数据结果 | 结论 |
|---|---|---|
| 向量距离可分（负例 law_min 更大） | 负例「遇到危险怎么报警」law_min=0.278，比正例最大值（0.368）还近 | **否决**，分布完全重叠 |
| BM25 分数可分（负例分数更低） | 负例「股票怎么买」23.24，高过一半正例（最低正例「中介费谈不拢」11.14） | **否决** |
| 案例侧零命中 ≈ 负例 | 正例 138 条里仅 5 条 case_pass=0；负例 62 条里 56 条 case_pass=0 | **唯一有效特征** |

原因：案例库全是真实裁判文书，生活/闲聊类向量天然够不到案例域；法条侧是规范文本，生活问题能蹭到近邻。

### 9.4 意图门控规则与标定

```
条件：case_pass ≤ 1（案例侧 ≤0.42 命中数 ≤1，原始计数、去重前）
    且 law_min > 0.35（法条侧最近距离，含阈值外候选）
→ 判非领域查询，整体拒绝（laws=[]、cases=[]、intent_rejected=True）
```

- 只在**法条/案例两侧通道都启用**时判定：文书生成（top_cases=0）、类案推荐（top_laws=0）、MCP 工具等单侧调用不受影响。
- θ 扫描（0.26~0.40）：0.35 是「拦截数/误伤数」在 200 条上的最优区间；0.345~0.355 之间挤着 4 条临界项（房东进入 0.345 / 驾照 0.350 / 股票 0.352 / 善意取得 0.355）——**边际很窄，阈值对分布漂移敏感，继续优化应换特征而非调参**。
- 标定探针与 production `retrieve()` 同参数（法条 n_results=8 取 min、案例 n_results=9 数命中）；生产实测拦 51/62（标定预测 50 条，差异来自 1 条临界项在未舍入距离下越线）。

### 9.5 三代对照结果（200 条集）

| | 误召回率（负例） | law hit@4 | case hit@3 | 负例误召条数 |
|---|---|---|---|---|
| **改前**（无条件召回） | 100% | 96% | 98% | 408 条 |
| **语义门控**（第一代） | 39% | 96% | 98% | 106 条 |
| **+ 意图门控**（现役） | **18%** | 96% | 98% | 53 条 |

- 语义门控在 200 条集下从 10% 回升到 39%——**不是变差，是评测集变难了**（新负例全是半专业沾边类）；意图门控压到 18%，垃圾引用 408 → 53 条。
- 正例召回零损失（96%/98% 三档不变）；96% 的缺口是 5 条**已知检索弱点**（楼上漏水、房东进入、见义勇为、股权质押、强制执行时效），非本次改动引入。
- 靶心闭环：第一代漏网的「股票怎么买」「你觉得我该不该辞职」在本代被拦截。

### 9.6 残余与已知代价（诚实记录）

- **残余 11/62 负例**（18%）：驾照/学车、开公司花销、汽车保养、创业、派出所、宠物证、亲子鉴定、「民法典一共多少条」、报警、存钱、征信污点。其 law_min 落在 0.278~0.350，与正例完全同带——**距离特征到此为止，这是语义意图分类问题**（收口方向：rerank / 意图分类器 / LLM 判定，取舍见 6.1）。
- **误拒 1/138 正例**：`什么是善意取得制度`——law_min=0.355 与「该不该辞职」**完全相同**、case_pass 同为 0，任何能拦住辞职的阈值必然误杀它。标定集上的硬性不可分，记录在案。
- 残余里 `遇到危险怎么报警`（case_pass=2）、`怎么存钱利息更高`（case_pass=9）连"案例侧零命中"都不成立——案例库真有相邻案由（危险驾驶罪、储蓄存款合同纠纷），词面却是生活问题。

### 9.7 回归命令

```
.venv/Scripts/python.exe scripts/retrieval_eval.py     # 三档对照 + 残余/误拒明细
```

评测脚本沿用"逻辑副本 + 历史快照"设计：`gate` 参数切改前/语义门控，`intent` 参数叠加意图门控——production 再演进，仍能回答"比改前好还是差"。
